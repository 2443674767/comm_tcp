# 邻语：Ubuntu amd64 离线部署

本包面向 **Ubuntu 64 位 Intel/AMD（x86_64/amd64）**。已包含 Linux amd64 程序和 Docker 镜像，无需安装 Go、Node.js，不需要在线编译或拉取应用镜像。

已有版本升级请先阅读《升级说明.md》，使用 `upgrade.sh` 自动备份并保留证书；本页 `install.sh` 用于新安装。

## 1. 服务器准备

服务器需已安装 Docker Engine、Docker Compose v2、OpenSSL、iproute2；非 root 用户部署还需 `acl`（提供 setfacl）。缺少时可安装 `sudo apt-get install openssl iproute2 acl`。运行部署命令的用户需能执行 Docker（或在命令前使用 sudo）。检查：

```sh
uname -m                    # 应输出 x86_64
docker version
docker compose version
openssl version
ip -4 addr
```

确保 18086/TCP、18087/UDP、18085/TCP 未被其他程序占用，并允许客户端连接这些端口。Ubuntu 已启用 UFW 时，可按实际网络策略放行：

```sh
sudo ufw allow 18086/tcp
sudo ufw allow 18087/udp
sudo ufw allow 18085/tcp
```

## 2. 解压、部署

将 `lan-chat-ubuntu-amd64-20261113-video-photo.tar.gz` 复制到服务器，然后执行：

```sh
tar -xzf lan-chat-ubuntu-amd64-20261113-video-photo.tar.gz
cd lan-chat-ubuntu-amd64
sh install.sh
```

安装脚本会检查包内 SHA-256 校验和、导入 amd64 镜像、自动识别**当前 Ubuntu 主机地址**、生成 HTTPS 证书、启动容器并检查健康状态。终端会打印访问地址：

```text
https://当前主机IP:18086
```

无需填写原来的 IP。多网卡时会列出多个地址，选择手机、电脑能到达的局域网地址。如果需要固定某个地址：

```sh
sh install.sh 10.0.0.20
```

默认使用 Linux host 网络；不可把本包的安装脚本用于 macOS、Windows 或 ARM 主机。当前 Mac 上的测试服务已停止，部署前需将包复制到 Ubuntu。

## 3. 手机、电脑首次信任证书

将 **服务器新生成的 `certs/ca.crt`** 复制到手机/电脑，安装并信任。不要分发 `ca.key` 或 `server.key`。本包没有包含开发电脑的证书或私钥，因此新安装需要信任服务器生成的 CA。

- **iPhone/iPad**：打开 ca.crt，安装描述文件（设置 → 通用 → VPN 与设备管理）；再到设置 → 通用 → 关于本机 → 证书信任设置，完全信任 `LAN Chat Local CA`。
- **Android**：在系统设置中搜索“安装证书”/“CA 证书”，选择 ca.crt 并安装。
- **Windows**：双击 ca.crt → 安装证书 → 当前用户 → 手动选择“受信任的根证书颁发机构”。
- **macOS**：导入“钥匙串访问”，打开证书，将 SSL 信任设置为“始终信任”。
- **Firefox** 若不采用系统信任：在证书设置的“证书颁发机构”中导入 ca.crt，信任用于识别网站。

然后用系统浏览器打开 `https://当前主机IP:18086`。先确认没有证书警告，再输入昵称、允许麦克风。仅跳过 HTTPS 警告不能保证录音/通话可用。手机与电脑均需能连接主机 IP；手机后台/锁屏可能暂停通话。

Linux 非 root 用户生成证书时，脚本只给容器 UID 0 添加 `server.key` 的读取 ACL；其他用户没有读取权限，CA 私钥不授权也不挂载。容器仍保持 `cap_drop: ALL`，无需额外 Linux capabilities。`ls -l` 会显示 ACL 的权限掩码，实际授权以 `getfacl certs/server.key` 为准。

## 4. 功能与端口

| 功能 | 说明 |
|---|---|
| 登录 | 输入昵称，无密码；可选择或创建频道 |
| 历史 | 各频道独立，文字与录音持久保存，新用户也能查看 |
| 频道 | 任意已登录用户可创建和命名；旧记录在公共频道 |
| 提示音 | 当前频道新消息；加入播报昵称后响两声，退出播报昵称后响一声；可关闭 |
| 录音消息 | 单条最多 120 秒、10 MiB |
| 群语音 | 每频道最多 5 人，服务器转发，不录制通话 |
| 通话时长 | 无单独时长上限；受网络、浏览器和 30 天登录有效期影响 |
| 18086/TCP | HTTPS 网页、文字、录音、语音协商 |
| 18087/UDP | 群语音主通道 |
| 18085/TCP | 浏览器支持时的 ICE-TCP 备用通道 |

优先确保 18087/UDP 畅通；TCP 备用不是 TURN，不能保证任意跨网环境可用。

## 5. 运维与数据

在解压目录中执行：

```sh
docker compose ps                         # 查看状态
docker compose logs --tail=100 chat        # 查看日志
docker compose exec -T chat /lanchat healthcheck
docker compose stop                       # 暂停
docker compose start                      # 恢复
docker compose restart                    # 重启
docker compose down                       # 移除容器，保留数据卷
```

Compose 项目名称固定为 `lan-chat`，数据卷为 **`lan-chat_chat-data`**，保存 SQLite 和录音。不要执行 `docker compose down -v`，该命令会删除聊天数据。

本包为全新部署包，**不包含开发电脑上的测试聊天记录、会话、录音和私钥**。旧源码版默认 Compose 项目名为 `tcp_comm`，其数据卷可能叫 `tcp_comm_chat-data`；本包不会自动读取或删除那个卷。如需旧数据，应先停止旧服务并明确迁移数据，避免误认为数据丢失。

一致性备份（停止后复制整个数据目录，包含 SQLite WAL）：

```sh
docker compose stop chat
mkdir -p backup
docker cp "$(docker compose ps -aq chat)":/data ./backup/data
cp -a certs ./backup/certs
docker compose start chat
```

备份包含私钥和会话令牌，仅由管理员保管。证书目录和数据卷应随部署一并保存。

## 6. IP 变化、续期和更新

迁移主机或 IP 改变后，在当前主机重新执行 `sh install.sh`（使用同一份原始部署包）；它会重新识别 IP、复用原有 CA、更新服务器证书并重建容器。保留原 `certs/ca.crt` 与 `certs/ca.key` 时，客户端无需重新信任。普通 `docker compose restart` 不会重新生成证书。

CA 有效期 10 年，服务器证书有效期 365 天，到期前重跑安装脚本即可续期。若修改了包内文件，校验会失败；可按以下步骤手动更新证书/重建容器，避免跳过或改写包校验来掩盖文件变化：

```sh
sh scripts/generate-certs.sh
SERVER_IP= docker compose up -d --no-build --pull never --force-recreate
```

更新到新版本时，先备份数据和 certs，导入新版镜像并使用新版部署文件；保留项目名称和数据卷，保留 certs 以沿用 CA。

## 7. 包内文件

- `lan-chat-image.tar`：可直接 `docker load -i` 的 Linux amd64 镜像。
- `lanchat`：Linux amd64 静态可执行程序，供需要原生运行时使用。
- `compose.yaml`、`install.sh`：离线安装配置和脚本。
- `upgrade.sh`、`升级说明.md`：已有版本的备份、升级和回滚说明。
- `scripts/`：本机地址检测、证书生成脚本。
- `Dockerfile`：从包内二进制重建镜像的可选入口，无外部基础镜像。
- `SHA256SUMS`：包内交付文件校验。
- `验证记录.md`：本次验证范围和结果。

`lanchat` 已静态编译，无需服务器安装 Go 或匹配特定 glibc。Docker 部署为推荐方式。
