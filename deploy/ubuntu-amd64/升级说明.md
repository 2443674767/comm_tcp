# 升级到拉人进语音版

版本：`2026.11.13-video-photo-amd64`。目标为 Ubuntu x86_64/amd64。

本版新增“拉人进语音”：在群语音卡片点“拉人进语音”，勾选任意在线伙伴（不限频道，可多选、全选）一起邀请，发起人未在语音中时先自动加入。被邀请者在任何频道都会看到来电卡片并听到循环铃声，可接受或拒绝，30 秒未应答算未接听；接受后自动切换到发起人所在频道并加入其群语音。铃声遵循“提示音”开关，关闭时只显示卡片。邀请只存在内存中，本版不改动数据库结构；从 `2026.11.11-voice-amd64` 升级不涉及数据迁移。

此前版本已有的功能：频道创建与选择；各频道的聊天、录音和群语音独立，每频道群语音最多 5 人。旧消息自动归入“公共频道”，频道名称和消息在重启后保留。当前频道的新消息播放提示音（自己的发送不提示）；真实加入／退出群语音时，当前频道所有在线用户均提示，包括没有加入语音的用户。加入时播报“昵称加入语音”后响两声；退出时播报“昵称退出语音”后响一声。刷新历史和在线名册不提示。

## 已有服务器的升级

本次只准备部署包，未远程安装。部署时，将新版压缩包与 `.sha256` 文件一起复制到 Ubuntu，解压到**独立的新目录**，不要先覆盖原部署目录：

```sh
sha256sum -c lan-chat-ubuntu-amd64-20261113-video-photo.tar.gz.sha256
mkdir -p ~/lan-chat-new-video-photo
tar -xzf lan-chat-ubuntu-amd64-20261113-video-photo.tar.gz -C ~/lan-chat-new-video-photo
cd ~/lan-chat-new-video-photo/lan-chat-ubuntu-amd64
sh upgrade.sh /home/unitree/lan-chat-ubuntu-amd64
```

升级脚本会校验包内文件和镜像架构，导入镜像，给旧镜像保留回滚标签，停止旧容器，然后备份整个 `/data`（SQLite、WAL、录音）、原 Compose 文件和证书到原目录的 `backups/时间戳-进程号/`。备份成功后才更新部署文件，检查原项目名为 `lan-chat`，读取容器实际使用的 `/data` 命名卷并在新配置中显式保留，然后重建容器、检查健康状态。绑定目录等自定义数据挂载会在停服前被拒绝，需要手动迁移。

升级后的 Compose 会记录实际数据卷名称，因此与包内模板的校验和不同；不要在原目录重新运行 `install.sh`。续期证书请按《部署说明》使用 `scripts/generate-certs.sh`。

原 `certs/` 及私钥 ACL 保持不变，无需重新信任 CA。旧聊天记录保留在公共频道；网页刷新后显示新版界面。端口仍为 18086/TCP、18087/UDP、18085/TCP，不需要为频道再开放端口。

升级期间现有网页和通话会断开，网页自动重连，群语音需重新加入。备份失败时脚本尝试恢复旧服务；启动新版失败时停止服务，并显示备份位置供检查和回滚。备份含会话令牌和私钥，请仅由管理员保存。

新安装使用 `sh install.sh`，详见《部署说明》。对已有服务应使用本页的 `upgrade.sh`，以先备份并保留现有证书。

## 回滚

不要只换回旧镜像：旧程序不认识频道，会把新版不同频道消息混在一起。回滚应同时恢复升级前数据。以下方法将备份装入一个**新数据卷**，保留升级后的卷供后续恢复，不删除原卷。回滚后仅能看到备份时刻之前的数据。

在原部署目录执行，先将 `backup` 改为升级脚本输出的实际绝对路径：

```sh
cd /home/unitree/lan-chat-ubuntu-amd64
backup=/home/unitree/lan-chat-ubuntu-amd64/backups/实际时间戳-进程号
test -f "$backup/data/chat.db" && test -s "$backup/image-id.txt" || exit 1
docker compose stop chat
restore_volume="lan-chat_restore_$(date +%Y%m%d%H%M%S)"
docker volume create "$restore_volume"
restore_container=$(docker create --platform linux/amd64 --mount "type=volume,src=$restore_volume,dst=/data" "$(cat "$backup/image-id.txt")")
docker cp "$backup/data/." "$restore_container:/data"
docker rm "$restore_container"
cp "$backup/compose.yaml" compose.yaml
cat > rollback.override.yaml <<CONFIG
services:
  chat:
    image: $(cat "$backup/image-id.txt")
volumes:
  chat-data:
    external: true
    name: $restore_volume
CONFIG
SERVER_IP= docker compose -f compose.yaml -f rollback.override.yaml up -d --no-build --pull never --force-recreate
docker compose -f compose.yaml -f rollback.override.yaml exec -T chat /lanchat healthcheck
```

回滚后操作服务须携带上述两个 `-f` 参数。再次升级前需将已恢复数据卷的配置合并到主 Compose 文件，避免重新接回未回滚的卷。旧 CA 和证书未被升级改动，无需恢复证书或移除客户端信任。

## 提示音与昵称播报使用

每台设备登录或恢复页面后，点击／触摸页面一次启用声音。昵称播报使用设备的本地中文语音引擎，不向云端发送昵称；连续事件排队播放。设备未提供本地中文声音或播报失败时，页面显示“中文播报不可用”，仍保留加入两声、退出一声提示。可在设备的文字转语音设置中安装中文语音后重试。侧栏或手机顶部有“提示音：开／关”，设置保存在当前浏览器中。声音关闭时仍显示消息和语音进出文字提示；浏览器或系统音量静音时不会听到声音。

手机锁屏、后台网页被系统挂起时，不能保证实时提示和通话；这不是系统推送通知服务。声音自动播放需要用户交互，参见 [MDN Web Audio 最佳实践](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices)。

## 升级后检查

1. 旧公共频道历史和录音仍可读取。
2. 两台设备进入同一新频道，双向收发消息、录音；刷新仍保留。
3. 一台加入／退出群语音，另一台即使没有加入语音也听到对应昵称播报和两声／一声提示；关闭提示音后两者都停止。
4. 另一台切到不同频道后不再收到前一频道消息、语音和提示。
5. 同频道两台加入语音后可互相通话；切换频道自动退出本页原通话。
6. 两台设备各在不同频道，一台点“拉人进语音”勾选另一台：对方响铃并弹出卡片，接受后自动切到发起人的频道并进入通话；再分别验证拒绝、30 秒不应答、关闭提示音后只弹卡片不响铃。
