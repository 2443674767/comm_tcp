# 局域网公共聊天室设计

## 已确认需求
- Ubuntu 主机（默认自动识别当前部署主机 IPv4），Docker Compose 部署；手机、Windows、macOS 浏览器访问。
- 昵称登录，无密码；所有登录者进入同一个公共聊天室。
- 文字及录音消息持久保存，新用户、重新登录及服务重启后都可查看历史。
- 所有人可自由加入/退出群语音，默认 2 人，预计最多 5 人。
- HTTPS 18086/TCP；允许语音使用 18087 与 18085。无域名，接受安装并信任局域网 CA。
- 用户已选择服务器转发语音并明确要求开始开发。

## 方案比较与选择
1. 设备直连 WebRTC：服务端简单，但依赖设备相互可达。
2. Go/Pion 服务器转发 WebRTC（用户选择）：各设备只连接主机，固定媒体端口，适合当前网络约束。

## 架构
Go 单进程提供内嵌 HTML/CSS/JS、REST API、WebSocket 消息广播、SQLite 持久化和 Pion 音频 SFU。无外部 CDN 或云服务依赖。容器数据卷保存 SQLite 与录音，证书目录独立只读挂载。18086/TCP 提供 TLS；18087/UDP 提供复用 ICE；18085/TCP 提供 ICE-TCP 备用（并非 TURN，能否回退取决于浏览器和网络）。Docker 默认 Ubuntu host 网络，通告主机 IP，避免容器内部地址进入候选。

## builder decisions（实现默认值）
- 昵称 1–24 个字符；昵称只是显示名，允许同名，以随机会话 ID 区分。登录 session 保存在 SQLite，HttpOnly/SameSite cookie，有效 30 天。
- 历史按 ID 分页，每页 50 条；重连通过 ID 补齐，避免丢消息。发送使用客户端幂等 ID，防止重试重复。
- 文本最多 4000 字符；录音最多 120 秒、10 MiB，支持浏览器可录制的 WebM/Opus、Ogg/Opus、MP4/AAC。客户端检测支持类型，服务端限制大小和类型；文件读取必须登录。
- 群语音上限 5 人，文字聊天不设 5 人硬限制；显式加入、退出、静音，显示参与者。群语音不录制；录音与通话不同时占用麦克风。
- SFU 固定 5 个音频槽位，每个连接发送一条、订阅其他 4 条；无需动态 renegotiation。媒体使用 Opus，服务器只转发 RTP；槽位重新分配时连续化 RTP 序号/时间戳。
- 语音建立通过 HTTPS offer/answer，等待 ICE 收集；WebSocket 断开自动退出语音。客户端退出请求携带每次通话独立的 call_id，避免另一标签页或过期请求移除当前通话。页面返回前台重连后须主动重新加入，避免意外开启麦克风。
- 同一会话允许多标签页聊天；同时只允许一个群语音连接。
- 页面采用中文、浅色蓝绿配色；电脑左侧在线用户与语音面板、右侧聊天，手机纵向紧凑布局。历史加载、发送中、错误、断线状态可见；消息内容使用 textContent。
- 证书脚本只生成本项目 CA 和包含服务器 IP 的证书，不修改开发机或其他设备信任设置。CA 私钥不挂进运行容器。
- 不包含文件传输、私聊、管理员、消息删除、通话录制或手机锁屏后持续通话保证。

## 交付与验证
交付源代码、Dockerfile、compose.yaml、环境示例、证书脚本和中文 README。执行数据库/HTTP/WebSocket 集成测试、真实 Pion peer 媒体转发测试、race 检测、Linux 构建、Docker 构建/健康检查、桌面及手机宽度浏览器检查。当前开发机不是目标服务器，不声称已远程部署；实际手机麦克风权限、证书信任、目标主机防火墙需要现场验收。

## 自动使用部署主机地址（用户后续变更）
- 取消固定 IP；网页继续监听全部接口，浏览器通过 https://<主机IP>:18086 访问。
- `scripts/deploy.sh` 无参数时读取本机路由和所有 IPv4 地址，生成涵盖这些地址的证书，复用原有 CA，并构建/重建 Docker 容器。
- 默认清空 VOICE_HOST_IP，由 Pion 在 Ubuntu host 网络中自动发现本机地址。显式参数或 SERVER_IP 环境变量仍可指定地址。
- 迁移或 DHCP 地址变化后重跑部署脚本；不自动修改系统信任库。主机没有可用地址时明确报错。
