# LAN Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Build the agreed persistent LAN chat and five-person audio room, ready for Ubuntu Docker deployment.
**Architecture:** Embedded browser client talks to Go HTTPS/WS APIs; SQLite and disk audio persist on a volume. Pion forwards Opus RTP through fixed per-room tracks and single-port ICE muxes.
**Tech Stack:** Go, modernc SQLite, gorilla/websocket, Pion WebRTC, vanilla browser JavaScript, Docker Compose.
**Spec:** docs/superpowers/specs/2026-11-09-lan-chat-design.md

## Global Constraints
- Automatically discover the deployment host IPv4 addresses; HTTPS 18086/TCP, media 18087/UDP and optional 18085/TCP.
- Nickname only; shared text/audio history survives restarts; up to 5 voice participants.
- No external runtime CDN; no automatic CA trust changes; real-time voice is not recorded.

## Review Focus
- Reconnect races: broadcasts must not leave a permanent hole in history (task 2 / browser reconnect check).
- Persistence and retry: restart must retain audio/messages/session and duplicate sends must not duplicate rows (task 1).
- Authentication boundaries: history, media, signaling and WS require session; unsafe origins are rejected (task 2).
- Voice churn: departure/disconnect releases slot; subsequent participant audio still reaches peers (task 3).
- Small screens and media denial: usable controls, clear errors, microphone tracks released (task 4).
